# 第一阶段 Windows 实机验收

本地自动测试与代码对照已完成。这里的项目仍需在你的 Windows、实际 AstrBot 和 QQ 连接上验证。先用自己的测试私聊，不急着扩大到群聊。

## 开始前

记录 AstrBot 版本、Windows 版本、QQ 连接方案（以实际使用的 SnowLuma/NapCat/其他方案为准）、模型名称、后台端口和配置包版本。不要在公开记录中填写完整 UMO、QQ 号、密码或 Key。

复制 `验收记录模板.md` 为包目录外或 `.local` 中的本地记录。先在 QQ 发“在吗”，确认原连接能正常回复。

## 1. 导入与检查

1. 解压整个候选包；不要只取 BAT。
2. 在目标私聊发 `/sid`，复制完整 UMO。
3. 双击 `导入鱼鱼.bat`。填后台地址、账号密码和 UMO；确认预览显示的是这个会话。
4. 完成后双击 `检查鱼鱼.bat`。应看到 `ok: true`，并显示鱼鱼人格与专用配置 ID；`qq_acceptance: pending` 是正常的。
5. 打开后台核对：原配置没有改，新建了一份鱼鱼专用配置；目标会话绑定到它；会话人格是 `鱼鱼_温和搭子_v02`。

错误时保留报错文字和 `.local`。反馈前遮住身份信息。不要把“创建人格成功”单独当成整套配置成功。

## 2. 人格与说话方式

正常聊 5–10 轮，可使用：

| 输入 | 观察标准 |
|---|---|
| 你叫什么？ | 能以鱼鱼身份回答；不继续使用旧角色名 |
| 今天有点烦 | 自然接话，不突然写长篇说教 |
| 不想说 | 接受停止，不连续追问 |
| 还挺聪明 | 有自然反应；不要求复现某条固定例句 |
| 我不是那个意思 | 简短承认接岔，回到实际话题 |
| 帮我把这个设置步骤讲清楚 | 能正常说明，不为短句人设漏掉必要步骤 |

人格表现受模型和已有历史影响。此前历史大量使用旧人设时，可在后台保留旧对话并新建一段测试对话；不要把 `/reset` 当作每次验收的必做步骤。

## 3. 分段与打字等待

先发送下面这句，仅用于验证分段，正常聊天不需要这样指定：

> 请原样回复下面两行，每行单独一行，不要加其他内容：
> 收到，我在。
> 今天先把聊天接通，其他事情慢慢来。

通过标准：QQ 收到两个文字气泡；第二个不是与第一个瞬间一起到达；较长的第二段一般等待更久。默认等待约为 `log₅(字数+1)` 到该值再加 0.5 秒。模型生成、网络和 QQ 发送还会带来额外延迟，不要求精确秒表一致。

再正常聊三轮，确认没有为了分段而一个字一条。最后问一个需要较长说明的问题，确认长文完整，没有被正则删字。

若总是一个气泡：先检查模型是否真的换行、是否超过长文阈值、是否有第三方插件直接发送；再检查目标会话实际绑定的配置。若毫无停顿，确认分段开启、间隔为 `log`，流式回复关闭。

QQ 是否显示“对方正在输入”不属于通过标准，本包没有实现该状态。

## 4. 范围、重复安装、恢复

| 项目 | 操作 | 通过标准 |
|---|---|---|
| 目标范围 | 查看另一个未绑定会话的配置；若方便，可自行发消息验证 | 未被换成鱼鱼专用配置 |
| 重复安装 | 再运行导入工具，输入相同信息 | 返回 `already_installed`；没有重复创建人格和专用配置 |
| 恢复 | 运行恢复入口 | 原会话绑定与本轮改动字段恢复；模型与 QQ 仍正常 |
| 恢复后再装 | 再运行导入并检查 | 可以配置成功；保留的旧专用配置可之后手动清理 |
| 人工修改保护 | 在测试专用配置里调一项节奏，再运行检查 | 检查指出差异，不悄悄覆盖；这是预期保护 |

最后一项可在主要流程通过之后做。确认验收完成后，把需要使用的最终设置保留下来；不要为追求检查全绿覆盖自己的有意调整。

## 5. 什么时候发布

上面“导入、人格、分段、打字等待、范围、重复、恢复、重装”通过后，记录实际环境和日期，再发布正式教程版本。失败就保留候选标签、修复、针对失败步骤重测。

如果你想测试“用户拿到 GitHub 链接，Agent 从头照做”的体验，可以先放候选版仓库供小范围验收。GitHub 上的可下载状态不代表质量已验收，不要提前改成“实测可用”。
