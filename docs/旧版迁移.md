# 旧版迁移与表情插件检查

升级前保存旧目录及其中的 `.local`。本工具不通过删除状态来覆盖旧安装。

## 从 v0.2.0 更新

1. 在原 v0.2.0 目录运行恢复入口，确认原会话绑定恢复。保留该目录用于追溯。
2. 解压 v0.2.1 到新的目录，再按 INSTALL.md 安装。同一目录已有旧版记录时，也必须先恢复。
3. 新版人格为 `鱼鱼_温和搭子_v021`，旧人格保留，避免覆盖用户已经手动调整的内容。确认没有会话或配置引用旧人格后，可以在后台删除旧人格和不用的专用配置。

如果旧目录丢失，保留旧 `.local`，可将其复制到完整的新包目录后执行 restore；schema 2 的恢复记录兼容。不要把恢复记录分享给其他人，也不要把两个安装目录的状态混在一起。

## 从 v0.1 更新

先在旧包运行其恢复入口；无法自动恢复时按旧包的手动说明还原目标会话。不要清空整个路由表、删除其他会话规则或删除聊天记录。

旧版表情插件可能仍然运行。先使用本地后台凭证执行只读检查：

```powershell
python -X utf8 tools/manage.py cleanup --legacy --answers .local/answers.json --json
```

结果列出旧人格 `鱼鱼_温和搭子_v01`、引用它的配置及路由数量、会话规则引用数量，以及 `astrbot_plugin_yuyu_companion` 的启用状态。不输出其他会话的 UMO，也不改变设置。

若只希望目标会话停发表情，在后台打开旧表情插件配置，从其启用会话列表移除这个目标 UMO，保留其他会话和其他字段。

若明确希望所有会话停用旧表情插件，可以执行：

```powershell
python -X utf8 tools/manage.py cleanup --legacy --disable-plugin astrbot_plugin_yuyu_companion --answers .local/answers.json --yes --json
```

这只停用旧插件，不删除插件文件或其配置。操作前保存小范围状态到 `.local/legacy`，操作后回读状态。需要恢复表情时在后台重新启用该插件。普通 `install`、`restore` 和单独的 `cleanup --legacy` 都不会执行全局停用。

旧人格、原配置及路由可能仍被其他会话引用，所以工具只列出引用，不自动删除；逐项检查用途后再在后台清理。新包安装使用新的人格和专用配置。
